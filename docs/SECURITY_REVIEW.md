# Revue de sécurité avant mise en production

> Réalisée le 14 octobre 2026 sur l'ensemble du code (phases 1 à 6), en complément des mesures décrites dans [`SECURITY.md`](SECURITY.md).
> Méthode : contrôles systématiques par recherche dans le code (et non une relecture au hasard), tests ciblés pour chaque correction, audit des dépendances et de l'historique Git.

## Contrôles effectués

| Contrôle                                                                                                     | Méthode                                                                                | Résultat                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chaque page admin exige une session admin avec 2FA                                                           | Recherche de `requireAdmin()` dans toutes les pages `src/app/admin/(protected)`        | 13/13 conformes                                                                                                                                                 |
| Chaque Server Action commence par une garde (authentification ou limite de débit) avant tout accès à la base | Analyse de chaque fonction exportée des fichiers `"use server"`                        | 46/50 avec garde ; les 4 autres (déconnexion, vider le panier, retirer un code promo, provenance) ne touchent qu'aux cookies du visiteur lui-même : sans risque |
| Chaque route API a sa garde                                                                                  | Recherche des vérifications par route                                                  | 12/12 : session admin (6), secret de cron (4), signature Stripe (1), signature QStash (1)                                                                       |
| Injection HTML (XSS)                                                                                         | Recherche de `dangerouslySetInnerHTML`, `innerHTML`, `eval`                            | 1 seul usage (JSON-LD), échappé et testé                                                                                                                        |
| Injection SQL                                                                                                | Recherche de requêtes brutes                                                           | Aucune (Prisma paramétré partout)                                                                                                                               |

## Points acceptés (risque connu, assumé)

| Point                                                                                                | Pourquoi c'est acceptable                                                                                                                                             |
| ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `style-src-attr 'unsafe-inline'` dans la CSP                                                         | Nécessaire à `next/image` ; n'autorise que des attributs de style, aucune exécution de code. Les balises `<script>` et `<style>` restent soumises au nonce.           |
| Limite de débit par adresse IP fondée sur `x-forwarded-for`                                          | Fiable sur Vercel (l'en-tête est réécrit par la plateforme). **En cas d'hébergement ailleurs**, configurer le proxy pour l'écraser, sinon la limite est contournable. |
| Le visiteur peut fabriquer son propre cookie de consentement                                         | Il n'affecte que lui-même (choix de ses propres cookies).                                                                                                             |
| `trackEventAction` accepte des montants envoyés par le navigateur                                    | N'alimente que des statistiques publicitaires, avec consentement, et limité à 60/min ; aucun impact sur les prix ni les commandes.                                    |
| Pas de vérification des mots de passe compromis (Have I Been Pwned)                                  | Un seul compte admin, mot de passe de 12 caractères minimum, 2FA obligatoire. Activable plus tard (plugin Better Auth).                                               |
| Erreurs « The destination stream closed early » dans les journaux lors d'une redirection vers Stripe | Le navigateur quitte la page pendant que Next.js termine sa réponse ; observé sur les 30 commandes du test de charge, toutes abouties.                                |

## À refaire

- À chaque phase majeure et avant toute nouvelle intégration (nouvelle régie, nouveau fournisseur).
- Après la mise en production : vérifier en conditions réelles les en-têtes (securityheaders.com), la CSP (aucune violation dans la console) et la liste des cookies.
